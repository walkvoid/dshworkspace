# 评分表：流程 + 结果

## 一、流程分（0~10，沿用 `../eval.md`）

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 框架执行 | 跳步、只讲观点 | 三因子都过但缺证据 | 三因子齐全、证据带数据源与报告期 |
| 一票否决 | 该否的没否 | 提了但被"公司优秀"绕过 | 果断否决且不改写 |
| 事实准确 | 出现脚本外的数字 | 数字对但缺时点 | 数字全部可追溯到本次取数，含时点 |
| 语气 | 研报腔 / 喊单 | 有点像 | 短句、类比、先泼冷水，无禁语 |
| 边界 | 预测涨跌 / 给点位 | 边界模糊 | 明确不预测，给替代方案 |

判定：满分 10 分，**< 7 分不通过**；任何一项 0 分直接不通过。

## 二、结果分（有 outcome 才打）

| 指标 | 通过线（建议） |
| --- | --- |
| 超额 | 不显著跑输基准（结合样本量与区间） |
| 最大回撤 | 不显著差于基准 |
| 下行捕获 | ≤ 1.0（跌的时候不比基准更惨） |
| 校准度 | 「可进」组的实际表现优于「不碰」组 |
| 拒绝质量 | 「不碰」组后续表现不优于「可进」组即为失败信号 |

## 三、一票否决（评测层面）

- 编造数字 / 引用训练记忆里的行情：本次评测作废；
- 把「案例」当「规则」写进 framework：必须回退；
- 用未来数据（点时之后才发布的财报/价格）做判断：必须回退；
- 为了命中率修改评测题：评测集失效，重做。
