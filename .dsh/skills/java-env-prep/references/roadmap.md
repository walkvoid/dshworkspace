# Java 程序员技能包：七模块路线图

每个模块是一个独立技能目录，共享 `env-profile.json` 与「仓库/工具链」约定。
当前只有**环境准备**落地，其余按顺序补。

| # | 模块 | 解决什么 | 产物 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 环境准备 `java-env-prep` | 把资料里的连接信息变成能用的环境 | `env-profile.json`、MCP 片段、nacos 配置、克隆好的仓库、日志脚本 | ✅ 已实现 |
| 2 | 项目导览 | 让模型在陌生仓库里快速定位：模块划分、启动类、接口入口、数据表 | 结构图、关键类清单、调用链 | 待做 |
| 3 | 需求分析 | 把 PRD/一句话需求拆成可落地的改动点 | 影响面清单、接口变更、表结构变更 | 待做 |
| 4 | 代码编写 | 按团队规范产出代码改动 | patch / 新文件 + 自检 | 待做 |
| 5 | 单元资产 | 补齐单测、桩数据、测试工具类 | 测试类 + 覆盖率报告 | 待做 |
| 6 | bug 修复 | 从日志/异常栈定位到修复 | 根因、修复 patch、回归验证 | 待做 |
| 7 | 上下检查 | 提交前自检：编译、静态检查、规范、影响面 | 检查报告 | 待做 |

## 模块之间的契约

- **模块 1 的输出是 2–7 的输入**：连库、查日志、跑构建都依赖 `env-profile.json`；
- 模块 2 产出的「关键类索引」被 3、4、6 复用；
- 模块 5、7 的检查项来自团队规范，应放 `references/team-conventions.md` 统一维护，避免每个模块各写一套。

## 目录约定

```
.dsh/skills/java-env-prep/      # 模块 1
.dsh/skills/java-project-tour/  # 模块 2（待建）
...
```

每个技能独立、可单独安装；共享资料放各技能的 `references/`，不要跨技能互相 import。
