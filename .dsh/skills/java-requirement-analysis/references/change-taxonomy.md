# 改动大类（change taxonomy）

12 类固定枚举。归类看**改动的落点**，不看需求的措辞；一条子需求一个主类，跨类放 `secondary`。

## api —— 接口新增 / 变更

- **信号**：新增接口、加参数、改返回体、改错误码、Dubbo/Feign 契约变化。
- **落点**：Controller、Dubbo 实现、Feign 客户端、API 模块的 DTO。
- **必查**：调用方（`find` 服务名 / 路由）、网关路由、接口文档、鉴权注解。
- **基线**：改已有接口 0.25–0.5；新增查询接口 0.5；新增写接口（校验/事务/幂等）1.0。
- **坑**：只改提供方不改消费方；返回体加字段导致老客户端反序列化失败；分页参数默认值变化。

## model —— 字段与数据模型

- **信号**：加字段、改类型、加枚举值、改 VO/DTO 组装。
- **落点**：Entity、DTO/VO、MapStruct/BeanUtils 转换、序列化配置。
- **必查**：字段从表到接口的整条透传链（表 → Entity → DTO → VO → 前端）。
- **基线**：单字段透传 0.25；跨 3 层以上 0.5。
- **坑**：只加 Entity 没加 DTO；`@JsonIgnore`/序列化命名不一致；老数据该字段为 null 的兼容。

## schema —— 表结构与迁移

- **信号**：新表、加字段、加索引、改字段类型、刷数、归档。
- **落点**：DDL、Mapper XML、迁移/回滚脚本、数据修复 Job。
- **必查**：`data.json` 里这张表的读写点数量（`risks`）、是否有分库分表、上线窗口。
- **基线**：加字段/索引 0.25；新表 0.5；刷数/迁移 1.0–2.0（含回滚与校验）。
- **坑**：大表直接 `ALTER` 锁表；只加字段不改 Mapper；迁移没有回滚；生产历史数据为 null。

## flow —— 业务流程 / 状态机

- **信号**：审批节点、状态流转、分支条件、撤回/驳回、超时。
- **落点**：工作流定义（procdef）、`extHandler`、状态机、业务 Service 的流转判断。
- **必查**：`flows/index.json` 的节点与处理类、状态枚举、并发/重复提交。
- **基线**：改一个节点处理 1.0；新增分支/节点 1.5–2.0。
- **坑**：流程定义改了但历史在途实例不兼容；状态枚举加值但前端没映射；并发下重复流转。

## ui —— 页面与交互

- **信号**：新页面、表单、列表列、弹窗、校验提示。
- **落点**：前端工程、组件库、路由与菜单配置。
- **必查**：设计稿、组件复用、权限点、空态/错误态。
- **基线**：列表/表单 1.0–2.0；复杂交互（拖拽/树/富文本）2.0–4.0。
- **坑**：只估了“画页面”，没估联调与字段校验；老浏览器兼容。

## auth —— 权限 / 角色 / 菜单

- **信号**：新增菜单、按钮权限、数据权限（本人/部门/全部）。
- **落点**：菜单表、角色授权、拦截器/注解、数据范围 SQL。
- **必查**：现有权限模型（RBAC/数据权限实现）、默认角色、超管豁免。
- **基线**：菜单/按钮 0.25；数据权限规则 0.5–1.0。
- **坑**：忘记给默认角色授权导致上线即不可见；数据权限拼 SQL 注入。

## job —— 定时任务 / 批处理

- **信号**：每日跑批、补偿任务、清理任务、一次性修数。
- **落点**：`@XxlJob`/调度平台、分批读取、幂等与断点续跑。
- **必查**：调度平台是否要注册、执行时长、失败告警、重复执行。
- **基线**：简单任务 0.5；带分批/断点/补偿 1.0。
- **坑**：全表加载 OOM；任务重跑产生重复数据；没有失败告警。

## mq —— 消息与事件

- **信号**：发消息、加消费者、领域事件、最终一致补偿。
- **落点**：Producer、Listener、消息体 schema、重试与死信。
- **必查**：现有 topic/queue、消费组、顺序性要求、幂等键。
- **基线**：单生产/消费 0.5–1.0；加补偿 1.0。
- **坑**：消息体加字段不兼容老消费者；消费失败无限重试；没有幂等。

## integration —— 外部集成

- **信号**：第三方 API、签章、支付、OCR、文件存储、短信。
- **落点**：适配层（防腐层）、重试/熔断、回调验签、对账。
- **必查**：对方接口文档、测试环境、超时与重试策略、密钥管理。
- **基线**：简单 HTTP 对接 1.0–2.0；含回调/对账 2.0–3.0。
- **坑**：把对方 SDK 直接散落在业务代码；没做超时；测试环境不可用导致联调顺延。

## config —— 配置 / 参数 / 字典

- **信号**：开关、阈值、字典项、nacos 配置。
- **落点**：配置表、nacos、`@Value`/`@ConfigurationProperties`。
- **必查**：多环境是否都要配、默认值、灰度开关。
- **基线**：0.25。
- **坑**：代码上线了配置没发；默认值写死导致关不掉。

## query —— 报表 / 查询 / 导出

- **信号**：多表联查、统计口径、Excel 导出、大数据量分页。
- **落点**：Mapper XML、视图、导出工具、异步导出任务。
- **必查**：数据量（可用 `db.json` 行数）、索引、导出上限与超时。
- **基线**：简单查询 0.5；多表统计 1.0–2.0；异步导出 1.0–2.0。
- **坑**：`select *` 大表全扫；导出没有分页/流式；统计口径与财务对不上。

## nfr —— 非功能（性能 / 审计 / 兼容）

- **信号**：响应时间、并发、审计日志、幂等、向后兼容、灰度。
- **落点**：缓存、索引、日志埋点、限流、双写/开关。
- **必查**：SLA 指标、现有审计规范、回滚方案。
- **基线**：0.5–2.0，按验证成本估。
- **坑**：“顺手优化”没有验收标准；审计字段缺失；灰度没有回滚开关。
